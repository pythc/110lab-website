## 结论与修复

- 我的待办列表和详情区域按窗口高度独立滚动，筛选和应用入口不随列表增长。60 条虚构数据验证桌面与 375px 窄屏；滚到最后一项再点击，列表位置保留。
- 完整调用发现私有附件引用使用 `110lab://`，以数字开头的 scheme 无法被标准 URL 解析，导致附件读取报不存在。改为 `lab110://`，兼容旧引用输入，统一输出合法 URI。证书、简历、邮件附件三条路径均经实际 HTTP MCP 调用和 SDK 结果校验。

## 发布与回滚

发布前固定干净 Git 提交及 SHA-256 文件清单，核对线上容器、current、网关 inode/哈希和私有配置哈希。使用 SQLite backup API 备份数据，同时保留旧发布包、配置与网关。

升级时先暂停 MCP 写入和邮件领取，等待在途任务结束；新门户旁路健康检查通过后，只切换两个门户上游。停止旧门户内的邮件 worker 后再解除暂停；其他 worker 与考核容器不动。

回滚同样暂停领取并等待在途任务结束，恢复已保留的旧门户及网关，停止新版，然后恢复业务写入。**不恢复旧数据库覆盖新数据，不自动重发 UNKNOWN 邮件。** 本次不增加配置、不改变表结构。
