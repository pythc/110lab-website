# 招新邮件编写与投递（0.20.0）

招新工作台新增「写邮件」，由实验室管理员和 HR 使用。直接发送与候选人流程分开：不会建立虚构候选人、推进招新阶段或开放 Offer 名单。普通面试官无权查看或操作此入口和接口。

## 使用

1. 填写收件人，按需展开抄送、密送；逗号、分号和换行均可分隔。
2. 默认分别发送，每个 To 地址获得一封独立邮件；关闭后为一封含多个 To 的邮件。分别发送时，Cc/Bcc 会收到每一封。Bcc 仅进入 SMTP 信封，不出现在邮件头。
3. 选择已配置的发件邮箱、回复邮箱，套用已有模板或自由编写主题和正文。模板变量可以填共用值，并逐人覆盖。
4. 逐封查看服务器生成的预览，再确认发送。确认后查看发送记录；服务商接收不等于收件人已阅读或已进入收件箱。

模板用途包括面试邀请、投递回执、录取、未通过、预录取、补充材料、面试改期、入组通知、自定义邮件。新增模板时选择用途即生成可编辑样例；不覆盖现有模板，也不改变原有自动回执或录取规则。预录取样例使用通用称呼和 Offer 链接。

编辑器提供字号、文字颜色、底色、行距、四种对齐、编号/无序列表、表格、分割线、胶囊按钮及链接。图片可在光标位置插入、调整宽度、对齐和设置链接。链接在编辑面板填写，不依赖浏览器原生输入弹窗。字体在不同邮件客户端可能略有差异。

## 投递与安全边界

- 每批最多 50 个不重复的 To/Cc/Bcc 地址；每位操作人每小时最多 200 个实际信封收件地址。单张图片 2 MB，单封最多 8 张、合计 8 MB。
- HTML 由服务器白名单清理，图片使用私有存储和 CID 内嵌；脚本、外部追踪图片及危险链接会移除。变量值先转义。
- 预览绑定当前身份并保留 15 分钟。发送仅接受预览 ID 和摘要，不接受临时替换的正文；发件配置、当前权限在入队和真正投递前重复检查。
- 请求 ID 防止重复点击/网络重试重复入队。内容、投递任务、状态和审计在服务器 SQLite 持久化，沿用永久保留策略。
- 仅明确失败的任务可重试；连接中断、部分收件人被 SMTP 接收、进程中断等无法判断是否已发出的情况标为「结果待核实」，须填写核实依据再处理，不自动重复发送。
- 不新增凭证、收费服务、权限或真实测试邮件；沿用当前发信配置。

## 验证及升级

完整回归 255 项通过（含直接发送 10 项），覆盖权限/CSRF/同源/维护冻结、变量及地址校验、逐封和合并发送、Cc/Bcc、图片 MIME、幂等、限流、权限撤销、进程重启、结果不确定及安全重试。浏览器使用虚构账号和 example.com 地址验证预览、确认、模拟完成、记录回看和模板保存。SMTP 集成测试只连接本机虚构服务商，没有外发真实邮件。

本版增加 `direct_mail_previews` 表，不改已有候选人、简历、模板、HR、Offer 记录。发布须一起升级 HTTP 与招新 worker，先短暂阻止新写入、排空在途请求与投递，再备份数据库和旧发布。保持其他服务与私有配置不变，验证后恢复写入。

流量开放前失败可恢复旧 HTTP/worker 并保留数据库；开放后若产生 `kind=direct` 任务，不能直接恢复不认识该类型的旧 worker。先冻结写入和投递并核实任务状态，优先向前修复；必要时只回退页面/HTTP，保留能够处理直接邮件的新 worker。禁止用旧数据库覆盖新投递或发送结果。
