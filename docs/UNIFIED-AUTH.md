# 110lab 统一认证

身份源复用原飞书应用，统一入口为 `https://internal.110-lab.cn/auth`。不引入新密码，不按邮箱合并账号。跨服务以组织 ID 和 union_id 关联，在各应用内解析其自己的 open_id 或用户 ID。现有角色、内容权限和发送确认保持。

## 范围

工作台、项目、荣誉、招新、公共邮箱、动态使用同一门户会话。知识库通过注册的回调地址、S256 和一次性授权码取得独立身份凭证；网页和 MCP 子会话都保留中央撤销关系。考核管理使用已有管理员 SSO 通道，普通考生和批改系统账号保留。

需求 MCP 只恢复该用户已在平台授权的个人凭据。首次接入需要飞书平台确认，凭据用当前客户端临时 RSA 公钥加密后返回本机，用户无需复制连接码。确认页面的登录者必须与中央身份对应同一企业成员。平台自己的访问范围和角色仍生效，不把门户管理员角色映射为需求管理员。

## 协议与保存

中央身份凭据按 knowledge / requirements 区分 audience，绝不能跨服务使用。授权码 60 秒、登录准备 10 分钟；中央会话有效期从验证时固定 30 天。浏览器 Cookie 不跨域复制，服务凭据不暴露到模型参数或链接。门户 SQLite 仅保存凭据哈希；知识库关系凭据用 APP_SECRET 加密且绑定 session ID；客户端文件保持 0600。

知识库自身 OAuth 权限仍逐项确认。统一登录不等于一次授予全部操作权。成员离职、冻结、未激活、会话撤销或身份服务不可用时拒绝访问。管理员任免仍需最近 5 分钟验证；该步骤不会被 SSO 复用绕过。

## 发布顺序

1. 备份当前门户 SQLite、网关文件和容器元数据。并行启动门户候选，先保持考核 SSO 开关关闭。
2. 门户开启 PORTAL_UNIFIED_IDENTITY_ENABLED，注册知识库的精确回调。验收匿名访问、换码拒绝、OAuth 发现接口和既有业务。
3. 需求平台先发布接口和首次确认页面，再启用 LAB_IDENTITY_ENABLED / LAB_IDENTITY_TENANT_KEY。旧个人连接保留兼容，插件新连接必须同时携带中央凭证。
4. 知识库执行仅新增表的 20261014T070000 迁移，开启 LAB_IDENTITY_ENABLED。先测试隔离数据库，再更新本机主实例。
5. 考核 007 仅新增 SSO 表，外键锁等待最多 2 秒。保留原服务执行后台任务，新 HTTP 设置 ASSESSMENT_WORKERS_ENABLED=false，验证旧会话、材料和静态资源后热切网关。就绪后才启用 PORTAL_ASSESSMENT_SSO_ENABLED。
6. 最后更新同一私有插件。首次连接需用户本人登录并确认实际请求的服务权限。

## 回滚

不覆盖业务数据库、不执行 destructive down migration。先停止签发新 SSO 会话，撤销仅与统一认证关联的网页 / MCP 会话；考核须持有 lab-sso-issuance 锁并使用冻结文件，再切回旧 HTTP。保留所有考生、答卷、成绩、文件和旧版原生会话。知识库 down 在仍有统一会话时会拒绝执行。门户的旧 OAuth 授权保持兼容，新授权绑定中央浏览器会话。
