# 奖项荣誉与需求待办（0.12.0）

工作台「奖项荣誉」采用表格视图。成员登记名称、主办方、级别、等次、日期、获奖成员、关联项目与说明，保存草稿后上传一份 PDF/PNG/JPG 证书（5MB），然后提交审核。管理员复用实验室管理员名单，可通过、退回并填写意见。待审核进入管理员待办，退回进入提交者待办；审核通过的记录在实验室内部展示，不自动发布官网。

草稿、待审核、退回记录仅提交者和管理员可读。审核通过后修改资料或证书会回到草稿，必须重新审核。管理员可以归档和恢复为草稿。每次修改保留数据快照与审计，替换的证书也保留，产品没有永久删除入口。成员身份以飞书 subject 校验，客户端提交的姓名不可信，由服务器通讯录规范化。

数据库位于现有 PORTAL_MAIL_DATA 下的 workspace/honors/honors.sqlite，目录 0700、数据库 0600。证书存在私有数据库中，经登录权限校验后下载，不提供公开文件链接。事务包含记录、历史、证书与请求幂等键；revision 拒绝旧版本覆盖。默认证书存储容量 512MiB、单成员最多 500 条，总记录最多 10000 条；达到容量时停止新写入，不清除旧资料。

本地验证：`npm run build && node scripts/preview-honors.mjs`，在 127.0.0.1:4196/honors/embedded 使用虚构成员与管理员。仅监听 loopback，脚本和虚构数据均不进入发布包。

需求同步使用本机已配置的个人 MCP 连接，只读查询新工具 my_requirement_todos。平台按原工作台的 isMine（当前处理人 Open ID）及状态规则先过滤，再分页；排除已发布、已关闭。分页游标包含快照摘要，读取途中变化则重新读取一次，不将错误展示为成功的零条。旧平台回退到 handlers[].id 对认证后的 openId，达到 100 条标为不完整；PR 来源失败不清空需求。个人连接凭据始终留在本机，页面只获得紧凑待办与来源账号名称。

发布验证：新增 SQLite 使用原有私有挂载，无新密钥或部署环境变量。上线前备份现有发布包、Caddy 配置及私有数据库；候选验证后才切流。回滚 0.11.0 前暂停 /api/honors/* 的 POST 并等待上传排空，备份 honors.sqlite，再恢复旧 HTTP 上游。旧服务不读新数据库；保留该数据库及附件，禁止用发布前备份覆盖上线后的记录。招新继续 dry-run，所有已有邮件 worker 与管理员权限保持原配置。
