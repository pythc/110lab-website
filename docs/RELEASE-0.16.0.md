# 0.16.0 招新工作流发布候选

此版本把候选人、面试安排和审核保留在招新工作台，替换原来的目标表格同步。官网投递自动排队候选人回执；管理员分配飞书面试官，面试官登录回填，管理员逐人审阅后发送邀请；录取与未通过有独立模板和发送任务。支持变量、富文本和 CID 内嵌图片。

## 当前验证

- 源码全量回归：205 / 205 通过。
- 打包服务的 JSON-RPC 验证：37 个现有业务工具均完成真实本地 tools/call；全程 loopback 与虚构数据。
- 招新隔离测试：官网 multipart → 候选人 / 回执 → 面试官通知 → 鉴权回填 → 审核 → 图片邮件 → 录取 / 未通过。MIME 经解析验证收件人、Reply-To、正文及图片字节；SMTP 网络适配器通过本地测试服务器验证，Feishu 适配器检查实际请求格式。
- 浏览器：传统列表、模板图片上传保存、飞书成员选择、回填、逐人确认、录取分支和重启后状态保存已操作验证。
- 自行 review 修正：退回安排取消旧排队通知；过期回执不能通过旧失败任务再次发送；结果通知失败可重新预览；未知发送结果不重发；回执模板不允许未定义的面试变量；结果邮件沿用已安排面试官的回复邮箱；发布冻结拦截写入并停止领取新发送任务。

上述结果不代表真实 Feishu 或公网邮箱送达已验证。

## 未完成的发布条件

- 用户确认真实测试收件邮箱及仅本人 Feishu 目标。
- 默认根域 noreply 尚无服务器 SMTP 凭据；需确认先用已配置 notify 地址联调，或补齐根域私有配置。
- 招新工作流应用的现有 App Secret 尚未获准配置到此服务。
- 因此当前仍是本地候选，没有更改线上容器、共享网关、应用事件订阅或其他招新部署，没有真实外发。

## 配置和回滚范围

完整步骤见 [招新工作流说明](recruitment-workflow.md)。候选仅增加 mail_images 表和缺失模板，保留已有数据。真实联调保持全局 dry-run，HTTP 的邮箱/本人 subject 白名单与独立 worker 的收件白名单双重校验；凭据只挂给 worker。

上线前重新核对线上容器/配置/网关，冻结与排空、SQLite backup + quick_check、备份旧 release 和网关后再切换门户。回滚先停新 worker、冻结招新写入，再切回旧上游；不覆盖新数据库。旧版不能处理完整新流程，回滚后招新写入保持维护，其他应用继续可用。考核容器及其他招新部署不纳入发布范围。
