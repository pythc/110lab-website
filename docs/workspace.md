# 工作台 0.9.1

内部工作台新增项目空间与个人待办。公开官网仍只展示原有内容，内部项目不自动发布到官网。

## 身份与权限

复用公共邮箱的飞书身份和实时角色，将其产品含义统一为 **110 实验室管理员**，不复制另一套名单。现有超级管理员保持不变；只有超级管理员可以任免普通管理员和转让超级管理员。普通管理员共同处理项目立项、招新跟进，并继续拥有通知邮箱权限。邮箱成员同步进程保持原部署。

“周催办”是当前复用的飞书授权应用名。成员分别用自己的飞书企业账号登录，主体按 tenant_key + union_id 区分；名称不是共享账号。项目与公共邮箱共用身份，考核和需求平台保留各自登录。

工作台每次请求重新查询角色；撤权立即影响项目审批与招新操作。独立浏览器使用普通会话，插件工作台与公共邮箱在同一站点、同一顶层分区内复用 embedded 会话。二者 cookie 不可互换。POST 仍要求同源、CSRF 和有效会话。管理员任免仍要求近期再次认证。

## 项目与个人待办

- 从“应用 → 项目立项”进入 `/projects`（插件为 `/projects/embedded`），工作台上方只保留个人待办。成员创建自由探索项目；负责人或管理员维护简介、企业目录成员、GitHub 仓库、需求、文档及演示链接。
- 负责人提交立项说明后锁定项目资料，实验室管理员批准为共同项目，或填写原因退回。退回后可修改、再次申请。
- 里程碑指定项目成员和可选截止日期；仅负责人、管理员或被指派者可切换完成状态。归档后停止编辑和产生待办，恢复后继续。
- 个人待办包含分配给自己的里程碑、自己被退回的立项；管理员额外看到全部待审批项目和未处理的招新投递。
- 所有修改都有版本冲突检测，项目审计保留操作人、时间和原因。同一招新事项只允许一个管理员先行标记处理成功。

招新邮件状态独立于人工处理状态。邮件 SENT 不等于简历已审核；管理员的“已处理”只是跟进记录，不触发录取决定、不发邮件。候选资料按原有保留策略清理，工作台不公开或新增简历文件地址。历史条目清理姓名后仅显示回执编号，简历仍以原收件邮箱归档为准。跟进备注保留 30 天。

## 需求平台来源

桌面插件通过 app-only 工具 `get_my_110lab_requirement_todos` 读取本机已有个人连接。凭据只发送给现有需求平台，不上传门户服务器。上游成功验证 token 后，按其 employeeId 匹配当前处理人，按已验证 GitHub/飞书绑定匹配待评审 PR。界面标注来源账号，避免把两个应用的身份通过显示名误绑定。

只调用 `requirements_list` 与 `pull_requests_list`，不触发评审、通知、刷新写入或状态变更。现有 API 每类最多 100 条，没有分页；达到上限时明确标注“部分数据”，PR 缓存过期时明确标注。断连不是零待办。独立网页可使用项目和招新待办；个人需求来源只在已配置本机连接的桌面插件可用。考核待评审明细尚未跨系统接入，继续使用原考核应用。

## 数据及回滚

新增私有数据库位于现有 `PORTAL_MAIL_DATA/workspace`：`workspace.sqlite` 与 `recruitment-triage.sqlite`。目录 0700、SQLite/WAL/SHM 0600，禁止符号链接；不更改现有角色、OAuth 或会话表结构。不新增发信配置或服务凭据。

发布时备份原 release、代理配置、现有角色和登录数据库；若已有 workspace 数据，另做 SQLite 一致备份。候选先验证未登录/跨域写入被拒绝，再切换两个门户域名对应的上游。Caddy 原 inode 不替换，校验当前配置摘要防止覆盖其他项目改动。

回滚仅恢复 HTTP release 和门户代理上游，保留最新项目、处理记录、角色与登录数据库，不从备份覆盖在线数据。通知邮箱同步、简历发信、清理进程及考核服务均保持运行；回滚 0.8.14 会暂时隐藏新增界面，但再次升级可恢复数据。

## 企业成员选择

复用既有应用凭证，以 tenant_access_token 只读获取当前应用可见的部门和人员。遍历部门、分页、按 union_id 去重；缓存 60 秒、并发合并、失败退避 30 秒，最大 100 个部门、1000 位成员、单次 10 秒。错误不记录 token 或人员响应。只向已登录实验室成员返回 subject/name/可用企业邮箱，目录不写入登录身份或管理员表。

项目成员以企业 tenant_key + union_id 为唯一身份，可在首次登录工作台前选择。飞书未返回邮箱字段时保存空字符串，不伪造邮箱、不使用私人联系邮箱；登录本身仍必须由飞书验证企业邮箱和租户。添加项目成员不会授权管理员或通知邮箱权限。已存在项目成员在目录暂不可用时允许原样保留，不能借此新增任意身份。提交后再次校验当前会话和角色。

回滚注意：0.9.0 的旧成员选择器不理解尚未登录的目录成员，旧界面编辑可能丢失成员。因此 0.9.1 紧急回滚目标为保留的 0.8.14 稳定版本，暂时隐藏工作台项目/待办；保留最新 workspace 数据、角色、会话和邮件进程，再次升级恢复。禁止用备份数据库覆盖新项目。
