# 公共邮箱的插件登录

工作台保持匿名浏览。公共邮箱中的「飞书登录」调用仅向界面开放的 `connect_110lab_mail` 工具；HTTP 入口对缺失、无效或需要重新验证的身份返回 401 和 `WWW-Authenticate`，同时保留工具结果中的 MCP OAuth challenge，由宿主完成连接。匿名发现、资源读取和工作台工具仍返回正常结果，不能把整台 MCP 服务锁在登录之后。授权服务复用原飞书应用及 `/mail/auth/callback`，不增加飞书权限或发信能力。

流程：宿主注册客户端 → OAuth 授权页 → 飞书企业身份验证 → 展示当前身份并确认连接 → 带 `iss` 的宿主回调 → S256 PKCE 换取令牌 → 工具提供一次性页面凭证 → 原 iframe 凭自身 HttpOnly 绑定 Cookie 兑换 Partitioned 会话。页面凭证仅通过工具 `_meta` 返回，不进入模型内容。身份只从已验证令牌获取，工具参数不接受姓名、邮箱或 subject。

DCR 只接受 ChatGPT 官方回调及 Codex 本机 callback 路径。注册地址与实际回调严格匹配，只有本机回调允许变化端口。资源固定为 `https://internal.110-lab.cn/mcp/workbench-v6-1`，权限仅 `mail:session`。每次授权必须经用户确认，不能静默授予外部发起的客户端。

授权码 60 秒、只使用一次；访问令牌最长 30 分钟；刷新令牌轮换且复用会撤销该授权；身份总有效期 8 小时，刷新和页面登录都不会延长首次验证时间。管理变更仍要求 5 分钟内验证身份、CSRF 和名单版本；超时重新确认身份会撤销当前 OAuth 授权并要求重新登录。当前页面退出只退出页面会话；宿主连接可在插件管理中断开。

新增 `mail-oauth.sqlite` 位于现有 0700 私有目录，文件 0600；不含飞书 token，只保存本服务的授权状态、哈希令牌和注册资料。未完成流程 10 分钟清理，令牌在身份有效期结束后清理。配置变更清除旧授权。无新增密钥、付费服务或 SMTP 配置。

发布备份应包含这三个 SQLite 数据库：`mail-access.sqlite`、`mail-sessions.sqlite`、`mail-oauth.sqlite`。旧版可忽略新增的表和数据库；回滚只切换服务与页面，不恢复角色、会话、队列或动态的旧快照。

自动化验收使用虚构身份，覆盖 OAuth → MCP → iframe 会话、PKCE、精确回调、资源绑定、跨窗口拒绝、单次消费、刷新复用撤销、重启保留及管理员验证时效。正式宿主能否完成登录必须以实际插件授权返回后的页面状态为准，不能仅凭 HTTP 200 或测试通过宣称完成。

0.8.8 的实际客户端验证发现：工具级 challenge 被返回给页面，但 Codex 未开始 OAuth 注册，页面误以为宿主已打开连接授权。0.8.9 增加 HTTP 挑战，并用真正的 SDK HTTP 客户端验证发现元数据、DCR、跳转、令牌兑换和重试全过程。该测试不会访问真实飞书或外网，也不替代 Codex 原生登录验收。
