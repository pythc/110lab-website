# 公共邮箱的插件登录

工作台保持匿名浏览。公共邮箱中的「飞书登录」调用仅向界面开放的 `connect_110lab_mail` 工具；HTTP 入口对缺失、无效或需要重新验证的身份返回 401 和 `WWW-Authenticate`，同时保留工具结果中的 MCP OAuth challenge，由宿主完成连接。匿名发现、资源读取和工作台工具仍返回正常结果，不能把整台 MCP 服务锁在登录之后。授权服务复用原飞书应用及 `/mail/auth/callback`，不增加飞书权限或发信能力。

流程：宿主注册客户端 → OAuth 授权页 → 飞书企业身份验证 → 展示当前身份并确认连接 → 带 `iss` 的宿主回调 → S256 PKCE 换取令牌 → 工具提供一次性页面凭证 → 原 iframe 凭自身 HttpOnly 绑定 Cookie 兑换 Partitioned 会话。页面凭证仅通过工具 `_meta` 返回，不进入模型内容。身份只从已验证令牌获取，工具参数不接受姓名、邮箱或 subject。

DCR 只接受 ChatGPT 官方回调及 Codex 本机 callback 路径。注册地址与实际回调严格匹配，只有本机回调允许变化端口。资源固定为 `https://internal.110-lab.cn/mcp/workbench-v6-1`，权限仅 `mail:session`。每次授权必须经用户确认，不能静默授予外部发起的客户端。

授权码 60 秒、只使用一次；访问令牌最长 30 分钟；刷新令牌轮换且复用会撤销该授权；身份总有效期固定 30 天，刷新和页面登录都不会延长首次验证时间。管理变更仍要求 5 分钟内验证身份、CSRF 和名单版本；超时重新确认身份会撤销当前 OAuth 授权并要求重新登录。退出会撤销此设备的网页登录授权，并删除该授权关联的所有页面会话和未使用的登录交接凭据。独立授予的业务 MCP 权限仍按其自身授权管理。

新增 `mail-oauth.sqlite` 位于现有 0700 私有目录，文件 0600；不含飞书 token，只保存本服务的授权状态、哈希令牌和注册资料。未完成流程 10 分钟清理，令牌在身份有效期结束后清理。配置变更清除旧授权。无新增密钥、付费服务或 SMTP 配置。

发布备份应包含这三个 SQLite 数据库：`mail-access.sqlite`、`mail-sessions.sqlite`、`mail-oauth.sqlite`。0.15.0 增加两张授权关联表，既有表结构不变。回滚到 0.14.1 前必须删除关联到 OAuth 授权的页面会话与待兑换流程，防止旧代码忽略撤销状态；保留业务数据、角色和队列，不恢复旧数据快照。新页面只在服务端声明 restorePolicy=1 时恢复登录，因此回滚后不会静默恢复。

自动化验收使用虚构身份，覆盖 OAuth → MCP → iframe 会话、PKCE、精确回调、资源绑定、跨窗口拒绝、单次消费、刷新复用撤销、重启保留及管理员验证时效。正式宿主能否完成登录必须以实际插件授权返回后的页面状态为准，不能仅凭 HTTP 200 或测试通过宣称完成。

0.8.8 的实际客户端验证发现：工具级 challenge 被返回给页面，但 Codex 未开始 OAuth 注册，页面误以为宿主已打开连接授权。0.8.9 增加 HTTP 挑战，并用真正的 SDK HTTP 客户端验证发现元数据、DCR、跳转、令牌兑换和重试全过程。该测试不会访问真实飞书或外网，也不替代 Codex 原生登录验收。

0.8.9 的原生客户端日志确认返回 `Authentication required`，但依然没有启动 DCR。因此插件 0.8.7 的桌面端 `110lab` MCP 改为本地 stdio 桥接，公开工作台与资源仍从同一个 HTTPS 服务获取。只有登录操作由本地公共 OAuth 客户端处理：界面通过 `app.openLink` 打开 `_meta` 内的固定授权地址，本机仅监听 `127.0.0.1` 的随机端口，校验精确 Host、回调路径、一次性 state、issuer 和授权码后交由 SDK 完成 PKCE 兑换。`complete_110lab_mail_login` 仅对界面开放，等待回调后调用既有受保护工具；不能由页面提供身份。HTTP 401 校验继续保留。

此本地桥接需要 Node.js 20.11 或更新版本，不需要 npm 安装。0.15.0 起客户端注册资料和 mail:session 令牌保存于 `~/.config/110lab-login/oauth.json`；目录 0700、文件 0600，校验文件所有者、资源绑定并拒绝符号链接，原子写入且用跨进程锁协调轮换。PKCE verifier 仅存内存。页面登录使用 HttpOnly / Secure Cookie，嵌入页面额外使用 SameSite=None / Partitioned；绝对有效期为首次身份验证起 30 天，不因空闲、重启或刷新而缩短或无限延长。无需向插件分发飞书 App Secret。未完成的本机回调最长等待 260 秒，取消或超时会关闭监听；重复回调、其他来源 iframe、错误 state/issuer/Host 均不能完成登录。ChatGPT 网页和手机端不能运行这个本地 MCP 桥接。

界面通过短请求检查本机回调是否完成，不让一次 MCP 调用长时间等待用户授权，避免宿主的工具调用超时中断登录。授权码只通过 loopback 交给原本生成 PKCE verifier 的本地进程；轮询仍需原始页面状态，服务端兑换仍需该 iframe 的绑定 Cookie。

## 桌面端嵌入发布检查

切换 MCP 连接方式后，即使 UI domain 元数据不变，Codex 的沙箱来源也可能变化。0.8.7 的客户端日志已观察到两个新的 110lab 来源。发布时须将 `server=110lab` 的资源读取记录与沙箱记录对应，核对公共邮箱、动态管理和考核页面的 frame-ancestors 是否包含实际来源。仅添加已确认属于 110lab 的精确来源，不使用通配符。HTTP 200 不能证明浏览器允许嵌入。

## 持久登录升级与验收

首次升级时，旧内存凭据无法迁移，用户可能需要重新登录一次。既有会话和令牌保持数据库中原到期时间，不延长已过期授权。网页恢复由 iframe 自身绑定 Cookie、父页面校验、受保护 MCP 和一次性 ticket 共同完成；OAuth token 不进入页面、localStorage 或工具正文。重新打开有有效 Cookie 的页面无需调用恢复工具。Cookie 丢失但设备授权仍有效时，自动恢复同一身份；无凭据、到期或撤销时静默返回登录按钮。

管理员角色每次从现有名单读取，不缓存到 30 天凭据里。敏感管理员操作保留 5 分钟内身份验证要求。需求平台沿用独立的官方授权；考核接入开关保持当前部署状态，本次不修改考核容器。

本地虚构身份测试覆盖 7 天空闲后桥接重建、固定 30 天截止、退出同时失效 Cookie/刷新凭据/未消费交接、旧服务不自动恢复，以及原有 PKCE、回调和权限回归。实际 Codex 重启后是否恢复由部署后的原生插件验收确认。
