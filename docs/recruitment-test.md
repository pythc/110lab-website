# 招新流程测试空间

版本 0.10.0 增加工作台应用「招新流程测试」。入口 `/recruitment-test`，插件内入口 `/recruitment-test/embedded`。仅现有实验室管理员和超级管理员可使用，沿用飞书身份及每次请求实时读取的实验室角色。

## 范围

初始没有候选人。人工建立虚构候选人，邮箱仅允许 example.com、example.net、example.org 或 .test 域名。同一邮箱在同一组别不能重复建立。可填写简历摘要，并通过 Uppy 上传一份虚构 PDF/DOCX 简历（10MB 上限），不导入真实候选人资料。数据保存在私有 workspace 目录的 `recruitment-test.sqlite`，不读取正式投递队列、Gmail、飞书表格，不调用邮件、会议或通知服务。

流程：初筛 → 可选考核 → 面试安排 → 通知审核与模拟 → 面试反馈 → 决策 → 归档。考核、面试成绩都是管理员手动录入的测试成绩；不与正式考核账号或成绩关联。任一未结束阶段可记录理由并结束为未通过。已结束记录可以归档并查看历史。

模拟通知明确区分草稿、已审核、模拟失败、模拟发送成功，绝不表示真实邮件已发送。可模拟失败再重试；重新安排面试会生成新草稿并撤销旧审核。操作记录保留安排变更、审核、各次尝试、反馈与决策。最多 200 个候选人，每个 200 条操作。

## 组件选择

- 候选人采用传统表格列表，支持阶段、组别和姓名/邮箱筛选，按最近更新时间排序。点击姓名或详情按钮进入处理流程，阶段变更仍经服务端检查。
- [XState](https://github.com/statelyai/xstate) 5.33.2，MIT：服务端阶段及通知前置条件校验。纯状态转换在数据库事务中执行，不运行外部副作用，不取代持久化与幂等控制。
- [Uppy](https://github.com/transloadit/uppy)，MIT：复用项目既有 core 6.2.0 / Dashboard 6.0.1，通过共享会话适配器上传，实现测试简历选择、校验与反馈。官网原有投递继续使用 XHRUpload。
- [OpenATS](https://github.com/chamals3n4/OpenATS) 和 [FreeATS](https://github.com/freeats/freeats) 作为招聘体验参考。本次不引入整套独立系统及其额外服务。
- [用户提供的仓库](https://github.com/purplellllll/-) 作为流程参考，没有复制源代码。其已在使用的程序、数据与定时任务均不调整。

## 一致性与权限

SQLite 事务和 revision 保护多人并发；每次写入携带 requestId，同一操作因网络重试不会重复执行。变更请求体后复用 requestId 返回冲突。重试读取当前候选人，不能再次模拟发送。草稿审核绑定当前候选人版本。

API `/api/recruitment-test/` 及 `/api/recruitment-test/embedded/` 使用不同会话 Cookie 上下文。会话接口向已登录成员返回自己的身份和角色；普通成员会看到无管理权限提示，不能读取候选人或附件。业务读取需要实时管理员角色；写入还验证同源、CSRF、JSON 严格字段、16KB 内容限制及每分钟 60 次频率限制。官网主域名不开放此接口。所有记录只返回给已授权管理员，不增加公开 MCP 候选人工具。

## 测试附件

`POST candidates/:id/resume` 接收 multipart 字段 `requestId`、`revision`、`resume`。管理员身份、CSRF 和同源在接收前验证，文件读取及验证完成后再次检查实时权限和候选人版本。复用官网的 PDF 文件头/结尾、DOCX ZIP/XML/宏/解压体积检查。全局最多两个上传、每位管理员一个；未完成文件只留在有界内存中，无临时文件。上传成功后，元数据与 BLOB 同事务落库，总附件空间最多 100MB。

`GET candidates/:id/resume` 只向当前实验室管理员返回 attachment 下载响应，不产生公开文件 URL，返回 `private, no-store`。附件保留 30 天；启动及每五分钟清理一次，下载端即时拒绝过期文件。SQLite 开启 secure_delete，替换/到期删除会清理原 BLOB；运行数据之外的备份由备份保留规则管理。本地预览使用虚构管理员，绑定 127.0.0.1，不进入发布制品。

## 验证与发布

本地虚构流程测试覆盖可选考核、阶段限制、安排变更撤销审核、模拟失败重试、重复请求、并发冲突、归档与重启持久化；HTTP 测试使用真实会话适配器验证角色撤销、CSRF、Cookie 分区和主域名拒绝。附件测试覆盖伪造类型、大小、重复文件、重复请求、并发版本、上传中撤权、受控下载、重启及到期清理。界面另进行桌面及窄屏实测。

2026-10-05 本地验收：全量 141 项测试通过，构建及发布制品打包成功。浏览器走通新建、简历上传/下载、初筛、考核、面试安排、审核、模拟失败与重试、面试反馈、录取和归档；下载文件 SHA-256 与原文件一致。传统列表、阶段与组别组合筛选、空结果、归档详情、普通成员权限提示及窄屏布局均经过实测。集成测试关闭并重建整个 HTTP 服务，验证共用嵌入登录、候选人、操作记录、附件及幂等请求在重启后仍可恢复。脱离 node_modules 的发布运行包也走通完整测试招新流程。截图与测试输出保存在本地 `artifacts/recruitment-pilot/`，不进入发布制品。

当前仅提供本地预览，未部署到公网。预览的身份与候选人均为虚构资料；正式飞书授权以及 Codex 侧栏内的真实登录仍需部署后验证。`npm run preview:recruitment` 默认创建临时数据库，关闭进程后删除。需要保留体验记录时使用 `npm run preview:recruitment -- --data-directory artifacts/recruitment-pilot/local-data`；该目录保持私有，不进入发布制品。本次体验记录已备份至此目录并由新的预览进程继续使用。

发布仍复用现有 HTTP 容器、私有存储挂载和精确网关替换，不增加密钥或部署环境变量。备份现有私有数据库后激活候选，保留前一 HTTP 容器。回滚只切回旧 HTTP 服务和网关，不恢复或覆盖业务数据库；新测试数据库可留在私有目录供再次升级继续使用。正式发信、清理和邮箱成员同步进程不变。

如后续接入真实招新，需要单独核对数据源、候选人标识、通知审核与发送策略，以及现有程序的任务切换；本版本不自动接管。
