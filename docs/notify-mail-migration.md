# 管理员通知邮箱迁移

目标地址为 `noreply@notify.110-lab.cn`，迁入现有飞书企业邮箱，保留原地址。只有公共邮箱管理中的超级管理员和普通管理员获得此邮箱的原生使用权限。根域公共邮箱 `noreply@110-lab.cn` 的全员权限不属于本次变更。

## 迁移前置条件

- DNSPod 保存现有 `notify` MX、SPF、DKIM、DMARC 的精确值及 TTL；只先增加飞书域名验证 TXT。不得把两个服务商的 MX 混用。
- 在飞书建立专用公共邮箱，名称为「110lab 通知邮箱」。核实当前套餐发送额度能覆盖考核通知及简历投递；不购买新服务。
- 现有周催办应用增加官方公共邮箱管理权限 `mail:public_mailbox`，并在飞书的数据权限范围中选择「公共邮箱 包含 noreply@notify.110-lab.cn」，发布后检查指定邮箱可访问、根域公共邮箱被拒绝。服务端也固定为上述专用地址；不增加邮件内容读取接口或 SMTP 发信接口到插件。
- 用户完成公共邮箱 SMTP 凭证配置，凭证写入服务器私有文件，不进入仓库、命令参数、聊天或日志。先验证 TLS 和 SMTP AUTH，不发送真实测试邮件。
- 确认已有业务发送队列、重试状态和正在进行的考核。避免在发送中直接重建容器造成重复投递。

## 权限同步

新增 `server/mail-membership-worker.mjs` 独立运行，读取现有 `mail-access.sqlite` 管理员名单，以修订号为准。新增管理员、移除管理员、转让超级管理员都会触发重新对齐。

同步先撤销不在名单内的成员，再授予新成员；写入后重新读取并核验。并发角色修改会放弃旧快照并重新计算。单实例租约避免两个工作进程同时操作。失败保存错误码并按 15 秒至 5 分钟退避重试，成功后每 15 分钟核查权限漂移。

本地名单变更立即生效，飞书原生邮箱权限存在异步同步间隔；同步失败期间不能声称飞书已撤权。界面区分「管理员名单已更新」「权限待同步」「已开通收发」。登录失效、角色被撤销、工作进程心跳过期或修订号不匹配时，不显示可用状态。

启用环境变量：

```text
PORTAL_MAIL_NOTIFY_ENABLED=true
PORTAL_MAIL_DATA=/data/mail
PORTAL_MAIL_CONFIG=/run/110lab/mail.json
```

工作进程使用现有飞书应用私有配置和管理员数据库目录，配置只读挂载，数据目录可写。HTTP 容器只读同步结果，无法借由用户参数改变目标邮箱。工作进程不挂载 SMTP 凭证，也不读取或发送邮件。

## 切换范围与顺序

1. 冻结旧发布的提交、文件校验和、容器标识、网关配置、DNS 记录和两套 SMTP 配置。私有备份权限为 `0600`，父目录 `0700`。官网的 SQLite 使用在线备份 API，保留 WAL 中已提交数据；考核系统实际使用 PostgreSQL 的 `assessment` 数据库及同名 schema，须使用一致性 `pg_dump` 并检查归档可读取，不得把 `/data/uploads` 当作数据库备份。
2. 完成飞书域名所有权验证、邮箱建立、管理员成员授权和 SMTP 凭证验证。若飞书要求先切 MX 才能配置邮箱，暂停切换，重新安排受控窗口；不得先破坏正在使用的 DirectMail 配置。
3. 发布独立权限同步工作进程并确认其与当前管理员修订号一致，再开放新 HTTP 页面功能。沿用插件版本和现有精确嵌入来源，避免无关登录回归。
4. 在受控窗口切换 notify 的 MX、SPF、飞书 DKIM，并按实际启用状态调整 DMARC 报告地址。旧 DKIM 公钥可保留以便验证在途邮件；不要删除根域的阿里云 DKIM。
5. 仅迁移考核系统 SMTP 和官网简历投递 SMTP。二者使用相同通知地址。智评学堂的另一套发信账户不动。
6. 验证权威 DNS、TLS/SMTP AUTH、发信工作进程及考核健康、公共邮箱可见性和权限。公网首页、招新入口、视频、动态接口应保持原行为。没有外发测试时，报告不得称为完整外网投递验证。

重建考核容器前，重新核对 `assessment.email_outbox` 的发送状态，以及 `assessment.enrollments` 中尚未结束的考核。简历投递工作进程退出前，检查投递队列与有效发送租约；不得打断可能已进入 SMTP DATA 阶段的发送。SMTP 配置文件若为单文件 bind mount，原子替换宿主机文件不会更新现有容器挂载的 inode，必须在受控切换中重新创建相应容器并验证其实际读取的新配置。

## 回滚约束

- HTTP 页面回滚不停止权限同步工作进程，不恢复旧管理员数据库。管理员转让或撤销必须保留，避免撤销后的权限被旧快照恢复。
- SMTP 配置回滚与 DNS 回滚必须协调。只回退应用代码不能认为邮件链路已回退。切回 DirectMail 前要恢复并验证它要求的 notify DNS。
- 迁移后已经收到飞书的邮件不得删除，也不得通过回退 MX 将其视为已经迁回旧服务。DirectMail 没有收件箱。
- 保存旧容器和镜像，回滚前比对实际发布指针、容器身份和共享网关哈希；发现并发变更则停止覆盖并重新审查。
- 任何真实邮件投递失败都保留现有队列及诊断记录，不批量重放可能已经成功的发送任务。

此文档是迁移约束，不能代替现场验证记录。只有域名、邮箱、权限、SMTP 和依赖服务检查全部通过后才可宣告上线完成。
