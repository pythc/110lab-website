# 实验室统一身份

## 本次范围

| 应用 | 登录 | 管理权限 |
|---|---|---|
| 工作台、项目立项、荣誉、招新、公共邮箱 | 复用实验室飞书会话 | 既有成员/管理员/超级管理员规则 |
| 动态管理 | 改用同一飞书会话 | 实验室管理员、超级管理员 |
| 考核管理 | 工作台一次性授权码 + PKCE，交换为考核会话 | 当前仍有效的实验室管理员身份 |
| 需求平台 | 飞书妙搭原生会话，保留首次官方授权 | 妙搭原权限 |
| 内外网批改系统 | 保留独立账号 | 原规则 |
| 官网、考生入口 | 官网公开；考生账号保留 | 不因本次改造获得管理权限 |

## 考核认证

- 入口 `https://exam.110-lab.cn/api/auth/feishu/start`；插件加 `embedded=1`。
- 考核端保存 5 分钟 flow，绑定浏览器 HttpOnly Cookie、state、PKCE verifier 和嵌入上下文。
- 工作台页面使用已有会话，只有管理员可以以 CSRF 保护的 POST 签发 60 秒一次性授权码。
- 回调严格固定为 `https://exam.110-lab.cn/api/auth/feishu/callback`；无任意 redirect 参数。
- 服务端换码后只获得 audience=assessment 的独立凭证，不传递飞书 token、App Secret 或工作台 Cookie。
- 考核会话凭证以 AES-GCM 加密，绑定 session ID；每次认证向工作台检查原会话及当前角色，退出、过期、撤权后失效；认证服务不可用时拒绝管理访问。
- 本次新增管理员拥有独立身份映射和审计 actor，不按邮箱提升考生权限，不改写旧账号、作答和成绩。原有独立管理员账号保留运维恢复能力。
- 普通与插件 Cookie 保持分开，插件使用 Secure / SameSite=None / Partitioned。已安装插件资源 URI 保持不变。

## 配置和回滚

- 门户新增开关 `PORTAL_ASSESSMENT_SSO_ENABLED=true`，使用现有飞书配置；不新增密钥或飞书回调。
- 动态管理在生产环境要求实验室飞书模块已启用；配置遗漏会阻止候选启动，不会自动退回旧独立密码登录。
- 考核新增开关 `LAB_SSO_ENABLED=true`、`LAB_SSO_FREEZE_FILE=/run/110lab/sso-frozen`；迁移 `007_lab_sso` 仅新增三张表，等待旧表锁超过 2 秒就退出并回滚迁移。
- 新版 HTTP 使用 `ASSESSMENT_WORKERS_ENABLED=false`，原服务继续运行后台任务和处理在途请求。数据库、会话密钥和上传目录共用，不重启原服务。
- 发布前备份门户 SQLite、考核 PostgreSQL、当前镜像/容器/指针、共享 Caddy 配置；并行启动新版、核验旧 Cookie 和静态资源兼容，再热加载网关切换流量。详见 [无中断发布方案](ASSESSMENT-BLUEGREEN.md)。
- 先发布具备认证端点的服务，再更新插件入口。
- 回滚先创建 SSO 冻结文件，以数据库锁等待换码事务完成，再只删除 `lab_sso_sessions` 对应的会话。健康检查通过后，网关切至“旧后端＋两版静态资源”的回滚 HTTP 容器；新版继续处理已开始的请求。原考生会话、答卷、上传票据和后台任务保持。
- 回滚不覆盖业务数据库，不执行 down migration，不用旧快照抹掉发布后数据。
